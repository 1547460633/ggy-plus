# Spec Delta

## Purpose

让具备权限的后台用户安全地远程开关在线 ESP32 设备的灯，并能依据同一 requestId 查明实际执行结果或失败原因。

## ADDED Requirements

### Requirement: 有权限用户可以提交开灯或关灯命令
系统 SHALL 向拥有 `iot:device:control` 权限的已登录用户提供开灯和关灯操作。请求 MUST 包含非空 `requestId`，同一设备与 `requestId` 的重复请求 MUST 返回同一命令结果，不得重复下发硬件操作。

#### Scenario: 成功接受开灯命令
- **WHEN** 具备权限的用户向启用且在线设备提交新的合法开灯 `requestId`
- **THEN** 系统创建关联该 `requestId` 的待处理命令并向设备命令 Topic 以 QoS 1 下发开灯消息

#### Scenario: 幂等重试控制请求
- **WHEN** 用户以相同设备和 `requestId` 再次提交相同灯控请求
- **THEN** 系统返回原命令记录且不创建或发布第二条命令

#### Scenario: 控制权限不足或参数错误
- **WHEN** 无权限用户控制设备，或请求缺少 `requestId`
- **THEN** 系统拒绝请求且不创建命令

### Requirement: 离线、停用和并发命令具有确定结果
系统 MUST 拒绝对不存在、停用或离线设备创建远程控制命令，并记录可解释的失败原因。每台设备同时最多存在一条未终态灯控命令；新的不同控制请求 MUST 返回当前命令进行中的业务错误。

#### Scenario: 控制离线设备
- **WHEN** 用户控制已知为离线的设备
- **THEN** 系统不向 Broker 发布命令，并返回设备离线原因

#### Scenario: 同设备存在执行中命令
- **WHEN** 用户向已有未终态灯控命令的设备提交不同 `requestId`
- **THEN** 系统拒绝新请求并提示已有命令进行中

### Requirement: 设备回执和状态报告决定命令最终状态
命令消息 MUST 携带 `requestId`、命令类型、目标灯状态和过期时间。设备确认与状态上报 SHALL 回传同一 `requestId`；平台 MUST 将匹配目标灯状态的上报记为成功，将设备拒绝、发布失败或超时记为失败并保存原因。

#### Scenario: 设备执行成功
- **WHEN** 平台收到与未终态命令同一 `requestId` 且灯状态符合目标值的合法状态上报
- **THEN** 系统将命令标记为成功并记录完成时间

#### Scenario: 设备拒绝命令
- **WHEN** 平台收到与命令关联的拒绝确认及错误码
- **THEN** 系统将命令标记为失败并保存设备返回的失败原因

#### Scenario: 命令执行超时
- **WHEN** 命令超过配置执行期限仍未收到匹配的成功状态上报
- **THEN** 系统将命令标记为超时失败并保存超时原因

### Requirement: 用户可以分页查询指令记录
系统 SHALL 向拥有 `iot:command:list` 权限的用户提供指令记录分页查询，并向拥有 `iot:command:query` 权限的用户提供单条详情。记录 MUST 展示 `requestId`、设备、目标状态、命令状态、失败原因和关键时间，但不得暴露设备密钥。

#### Scenario: 分页查看命令记录
- **WHEN** 具备列表权限的用户按设备、状态或时间范围以合法分页参数查询
- **THEN** 系统返回统一分页结构和符合过滤条件的命令摘要

#### Scenario: 查询不存在命令
- **WHEN** 用户查询不存在的命令详情
- **THEN** 系统返回命令不存在且不返回伪造状态
