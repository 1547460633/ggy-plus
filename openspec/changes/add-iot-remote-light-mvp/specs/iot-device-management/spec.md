# Spec Delta

## Purpose

为后台人员提供 ESP32 点灯设备的受控注册、凭据轮换与设备信息查询能力，保证设备凭据可追溯且不会在后续查询中泄露。

## ADDED Requirements

### Requirement: 管理员可以预注册设备并取得一次性凭据
系统 SHALL 允许拥有 `iot:device:add` 权限的已登录用户创建启用的点灯设备，并在成功响应中仅一次返回 `deviceKey` 与 `deviceSecret`。系统 MUST 不在后续设备详情、分页结果或操作日志响应数据中返回 `deviceSecret` 明文。

#### Scenario: 成功注册设备
- **WHEN** 具备权限的用户提交名称、设备类型和合法备注创建设备
- **THEN** 系统创建设备并返回设备标识、`deviceKey` 与一次性 `deviceSecret`

#### Scenario: 无权限注册设备
- **WHEN** 不具备 `iot:device:add` 权限的用户请求注册设备
- **THEN** 系统拒绝请求且不创建设备或凭据

#### Scenario: 注册参数不合法
- **WHEN** 用户提交空设备名称或不支持的设备类型
- **THEN** 系统返回参数校验错误且不创建设备

### Requirement: 管理员可以轮换或停用设备凭据
系统 SHALL 允许拥有 `iot:device:credential` 权限的用户轮换已有设备的密钥，并仅一次返回新 `deviceSecret`。停用设备后，系统 MUST 将设备标记为不可连接且不可控制。

#### Scenario: 轮换有效设备凭据
- **WHEN** 具备权限的用户轮换已存在且启用设备的凭据
- **THEN** 系统使旧凭据失效并仅在该响应中返回新凭据

#### Scenario: 操作不存在设备
- **WHEN** 用户对不存在或已删除的设备轮换凭据或修改状态
- **THEN** 系统返回设备不存在且不产生凭据或状态变更

### Requirement: 管理员可以分页查看设备并查询设备详情
系统 SHALL 向拥有 `iot:device:list` 或 `iot:device:query` 权限的用户分别提供分页列表与设备详情。返回数据 MUST 包含设备基础信息、启停状态、在线状态、最近上报灯状态和最后活跃时间，且不得包含密钥明文或哈希。

#### Scenario: 按条件分页查询设备
- **WHEN** 具备列表权限的用户以合法分页参数和设备名称或在线状态筛选
- **THEN** 系统返回统一分页结构及符合条件的设备摘要

#### Scenario: 查询设备运行状态
- **WHEN** 具备详情权限的用户查询存在设备的详情或状态
- **THEN** 系统返回该设备最近已知的在线与灯状态信息

#### Scenario: 查询权限不足
- **WHEN** 不具备对应查询权限的用户访问设备列表、详情或状态
- **THEN** 系统拒绝请求且不返回设备数据
